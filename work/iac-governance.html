The problem & my role

An infrastructure request begins with intent: what an application needs and how it should operate. Turning that into consistent code requires both reusable building blocks and checks around the result.

I designed AI-powered IaC that turns natural-language requirements and architecture diagrams into Terraform assembled from an approved module catalogue. I also built IaC governance and validation workflows.

Current work at MSD

I am currently working with Wiz for Infrastructure as Code within the MSD project.

From intent to configuration

Interpret the input

GPT-4o Vision reads architecture diagrams. Natural-language requirements provide another entry point into the same infrastructure generation workflow.

Find approved building blocks

Vector search identifies relevant modules from an approved catalogue. Reusable Terraform modules cover VPC, IAM, ECS, EKS, EC2, Lambda, S3, load balancing, Auto Scaling and observability.

Check the structure

HCL parsing checks the generated configuration. The broader governance workflow adds ownership standards, policy compliance, secrets detection and drift validation.

Design principle: constrain the building blocks

Approved modules make standard infrastructure patterns easier to reproduce. The tradeoff to manage is how to handle requests that do not fit the catalogue without silently bypassing its boundaries.

Governance around the change

The documented governance work uses Terraform, Checkov, GitHub Actions, HCL parsers and Dynatrace. Current professional work additionally includes Wiz for IaC at MSD.

Ownership, policy compliance, secrets detection and drift validation are distinct checks. Their purpose is to make infrastructure changes easier to inspect and operate consistently.

The current Wiz work is recorded as an ongoing responsibility. This case study does not claim a specific Wiz integration architecture, enforcement mode or measured outcome.

What is demonstrated here

The public record establishes the workflow and technologies: diagram and language input, approved-module retrieval, Terraform generation and governance checks. A numerical reduction in provisioning time or policy findings is not published here.

The interactive infrastructure lab makes the approval boundary tangible. Select a prepared request, inspect its fictional configuration, and introduce public access to see the example policy gate block the plan.

The lab is a deterministic educational demonstration. It does not call an AI model, run Wiz or Checkov, access MSD systems or deploy infrastructure.

Engineering perspective

Generated configuration needs the same engineering scrutiny as other code. Syntax alone cannot establish whether a change matches the intended architecture or has the right operational ownership.

The useful design is a workflow that makes assumptions inspectable, reuses trusted modules and keeps validation visible before an infrastructure change proceeds.
