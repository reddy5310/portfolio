The problem & my role

Engineering, testing, architecture, database and operations teams need access to AI capabilities and relevant organizational knowledge. A shared platform provides a reusable foundation across those workflows.

I architected and scaled the cloud-native GenAI platform at MSD Hyderabad GCC. My work includes agentic workflows with MCP tool orchestration and human-in-the-loop approvals, as well as retrieval pipelines for engineering standards in Confluence and SharePoint.

This is a public summary of work described in my professional record. The architecture below is conceptual; it omits internal endpoints, data and deployment details.

The architecture

The foundation combines API Gateway and FastAPI with Lambda and ECS Fargate. Strands Agents SDK, Semantic Kernel and MCP support agent orchestration and tool use.

Knowledge as a platform capability

Retrieval uses OpenSearch and Aurora PostgreSQL with pgvector, with AWS Glue and source knowledge from Confluence and SharePoint. The goal is to make engineering standards and operational procedures discoverable in the workflows that need them.

Events and delivery

EventBridge, SNS, SQS and DynamoDB support event and state workflows. Terraform and GitHub Actions provide repeatable infrastructure and delivery.

Design principle: reusable capabilities

A shared platform lets multiple teams build on common infrastructure. The tradeoff to manage is the relationship between reusable services and each team’s specific context, permissions and workflow needs.

  • AWS Bedrock
  • Lambda

Governance & human oversight

The platform includes human-in-the-loop approvals and AI governance around agentic workflows. A model’s ability to propose an action is separate from the authority to perform it.

What the public architecture makes explicit

Retrieval supplies context; tools act on systems; approval boundaries preserve a human decision. These are separate responsibilities, even when they appear in the same user workflow.

Engineering perspective

Adoption and concurrency are useful starting points. A complete operational view also needs retrieval evaluation, tool reliability, latency, cost and escalation behavior.

Those measurements are not published here. The architectural lesson is to treat AI as an operated service with explicit boundaries and repeatable delivery, rather than a standalone model integration.
