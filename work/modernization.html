The problem & my role

Legacy Java 8 and 11 applications carry different dependencies, transaction frameworks and runtime assumptions. An upgrade needs to account for the application around the JDK.

I direct AI-powered modernization work across a 545+ enterprise application portfolio, covering discovery, runtime modernization, technology classification and migration planning. Within that broader scope, I built the Java Runtime Modernization Factory.

Portfolio scope is not the number of completed upgrades. The first-wave validation figure below is a separate, smaller cohort.

The delivery pattern

Discover and remediate

The workflow combines SISU AI code remediation, dependency upgrades and LLM-assisted analysis to move Java 8 and 11 applications toward Java 21 and 25.

Deploy and validate

GitHub Actions automates deployment to VMware Tanzu Application Service. Validation pipelines and production-readiness checks precede stakeholder acceptance.

Resolve the surrounding compatibility work

The work includes JDK compatibility, CAROL/JOTM transaction frameworks, Apache Tomcat integration, secrets and routing.

Design principle: one repeatable path

Standardizing the delivery sequence makes it possible to reason about progress across applications. The tradeoff to manage is preserving room for application-specific compatibility work within that common sequence.

Validation is a distinct milestone

Code remediation, deployment, validation and acceptance are separate steps. A successful automated transformation does not itself establish production readiness.

The factory brings validation and stakeholder acceptance into the delivery path. The first-wave measure records progress through upgrade validation, rather than claiming that every application is deployed in production.

Engineering perspective

The important unit of modernization is the validated application. Runtime versions matter, but delivery also depends on compatible dependencies, integration behavior and operational readiness.

This approach makes the stages visible enough to discuss with application owners, architecture, security and platform teams. It also keeps a clear boundary between automated remediation and the evidence required for acceptance.
